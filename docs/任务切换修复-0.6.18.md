在已部署基线 `f921517` 上完成程序候审后，独立审核又发现三项同一闭环阻断；本轮只形成程序侧本地候审提交，尚未上传或部署：

- 创建请求生命周期和当前任务语音所有权现分为两个共享谓词。明确“放弃连接新任务”只释放当前任务的发送/确认阻塞；未决创建账本仍保留查询、恢复及禁止重复创建能力。未放弃的 `unknown`/`unavailable` 与不一致记录继续 fail-closed，并显示“新建请求仍待核对”的暂停原因；`bound`、`rejected`、`not_found` 以及合法已放弃记录不再永久阻挡。
- 新增“换到目标任务”“切换任务到目标”“声伴，帮我换到目标任务”等受约束语法；“高斯泼溅这个对话”只移除明确会话尾缀。否定、引用、讨论、复合命令、未解析引用及版本数字保护保持；无逗号且称呼疑似误识别的短问候只本地澄清，不猜测执行。
- 候选确认后的实时 `read` 除核对同一 ID 外，还严格核对展示名称；名称变化时保留原连接并要求按新名称重新确认。
- 匹配总数大于五时保留并播报完整总数，明确只列前五项并提示缩小关键词或去设置查看。可辨识性按实际播报的四十字标签判断：冲突时先使用当前五项中的唯一目录末级；目录末级仍冲突/缺失时使用足以区分这些候选的最短安全 ID 后缀，不朗读完整本地路径。未展示候选不宣称已完成重名区分。
- context 实验只有在提示朗读结束后预计可恢复确认通道时才说“直接回答”。未知/不可读创建账本、归档/未知绑定、草稿或待核对发送等持续阻塞会明确原因，并只提供“在设置里选择”或“先关闭免唤醒实验后再唤醒”的真实入口；`observe` 不再错误提示普通唤醒。没有替用户改模式、放宽保护或扩大普通自由话语权限。

## 根因与证据

1. `切道生办V0.6.18任务。`：旧规则没有“切道”，且产品别名只支持“申办”。未解析后返回普通聊天路由。
2. `你好帅喂，切换到申办0.6.18免唤醒架构实现。`：短问候误识别令整句解析失败；即使提取查询，旧匹配也不能组合产品别名与标题中少一个“与”。
3. 现场只读检查发现目标 `01a0c431-8f20-7e23-b639-08764390d62f`：archived=0、本机主任务、记录文件存在，但 SQLite title 为空、session_index 无对应名称，任务工具读取 title=null。所以不是归档，也不只是 ASR；本地候选中存在 ID，但无法按名称找到。未确定名称缺失最初发生于创建、同步还是后续操作，不把推测当成结论。
4. 此前只打开 Codex 页面，声伴仍绑定原 ID；这不是连接切换。新回归核对绑定持久化及下一句的实际目标 ID。

按 [OpenAI 官方 App Server 文档](https://developers.openai.com/zh-Hans/docs/app-server)，显示名称可为空，设置后才由 thread/read 等返回；使用正式任务命名工具恢复已确定的“声伴 v0.6.18 · 免唤醒架构与实现”，未直接改私有数据库。随后生产只读 find 使用原关键词返回目标原 ID、unique、requiresConfirmation=true。此现场修复不是自动化任务管理测试。

## 修复边界与防回归

- 短问候修复仅接受“你好”开头、至多四个汉字、逗号后完整切换指令；排除否定、提问、举例，且强制候选确认。未知短前缀只本地澄清，不自动提取执行。
- 切道/切换道加入同音动词；生办/申办只在显式版本、独立产品词条件下建议声伴，字面名称优先。
- 标题最多允许漏一个“与/和”，两侧至少各两个汉字。查询有效文字不丢弃，版本数字不模糊，同版本多候选不代选。
- 空名称不猜、不读聊天正文补全；给出明确诊断。候选索引有空名称时，唯一可见匹配也需确认，防止漏掉真正目标却自动绑定其它任务。
- 新建/接续任务增加“正式名称写入→生产候选同 ID 名称回读”门槛。独立 GitHub CI job 覆盖解析、标题元数据、匹配和模拟语音到绑定/下一次投递，不依赖旧组合测试结果。
- 保留草稿、未知发送不重派、旧异步失效、目标实时验证等保护。免唤醒仍保持原设置；未擅自扩大普通自由话语执行权限。
