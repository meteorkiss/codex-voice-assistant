# 声伴：简单操作快执行，复杂工作交给 Codex

2026-09-08。建议先采用“本地常用指令 + 当前 Codex 任务”，把日常操作的等待去掉。小模型作为后续可选项，不为换声音再安装一个完整问答系统。

## 三条路径

| 路径 | 适用内容 | 处理方式 | 当前状态 |
| --- | --- | --- | --- |
| 本地直接执行 | 换台湾女声、语速慢一点、取消置顶、显示字幕 | 现有本地语音识别转文字，匹配明确指令，软件修改设置并回应 | 已实现，0.6.2 |
| 小模型理解口语 | “还是用刚才那个女的，说得稍微慢一点”这类需要联系设置上下文的说法 | 可选模型只识别设置意图，返回受限操作；不确定就保留原话交给 Codex | 方案，未接入 |
| 当前 Codex 任务 | 讨论方案、分析资料、写文档、操作项目 | 保留原始文字，发送给绑定任务，继续沿用其模型；完成后读答案 | 已有 |

第一条不再等待 Codex 查文件、改配置和重启声伴。它省掉的是远端处理与人工维护式操作的时间；目前仍有约两秒的停顿检测，以及实际语音识别、在线合成和播放准备时间，不能把“本地指令执行快”当成“端到端零等待”。

初期不要让小模型先改写每一句话。口头重复、文件名、数字、否定词和限制条件，都可能在所谓“整理”中丢失。确需整理时，保留原话，将整理内容作为辅助；不要只把摘要交给 Codex。

## 小模型怎么加才合适

如果这里的 LM 指 LM Studio，它可以在本机提供模型服务，程序通过本机接口调用；模型下载后，本地推理不需要互联网。[LM Studio 官方说明](https://lmstudio.ai/docs/app/offline)

适合把它用于“理解你要改哪个设置”，而不是让它自己改代码。模型只能从软件已实现的声音、语速、样式等操作中选择；软件再校验参数并执行。LM Studio 提供按 JSON Schema 返回结构化结果的接口，但格式正确不等于意图判断正确，模型兼容性也需要实测。[结构化输出文档](https://lmstudio.ai/docs/developer/openai-compat/structured-output)

明确指令始终先走本地规则，不额外调用模型。需要模型理解的请求设置有限等待；服务未启动、超时、参数不合法或含糊时，保持原始文字走既有 Codex 路径。它不获得任意系统命令执行权，也不自行切换任务。

目前不指定 DeepSeek 的具体版本，不下载模型。后续先采集你常用但未命中的说法，再比较扩充指令与增加模型的效果；如确需模型，再结合本机内存、显存和实际延迟选型。语音转文字已经使用本地 SenseVoice，增加语言模型不是让声音变成文字的必要条件。

## 先解决录音混入背景对白

本轮记录显示，录音持续超过 226 秒，随后在五分钟上限结束；转写中也出现长段电视剧对白。现有采集器以音量活动刷新最后发声时间，程序在连续两秒没有活动后结束问题。背景对白可以持续刷新这个时间，所以单纯换问答模型不会缩短这段录音。

建议按以下顺序改进，以下内容仍是方案：

1. 将短指令与长口述区分。短指令达到较短时限后停止并保留待确认文字，提供“继续说”，不要把达到时限的全部背景声音自动提交。
2. 增加清晰的结束与取消操作，保留现有点击结束入口；如要支持“说完了”“取消”，需做流式识别或独立关键词检测，不能等整段录音结束后才判断。
3. 用人声检测改善噪声造成的拖尾，并测试针对用户本人的收音。人声检测本身仍会把电视剧对白视为人声，不能承诺单靠它排除旁人讲话。
4. 排查电脑媒体声音进入麦克风与回声参考的实际路径。当前已验证的是助手自身播放的回声处理；电视、手机和其他播放设备需分别测试。需要时再评估近讲麦克风、声纹或说话人分离。

实现时保留唤醒后的音频缓冲，但将唤醒词尾音与“真正开始说问题”的检测分开，避免把尾音算作问题、影响无问题超时。固定的短确认还可预先生成并缓存，减少每次等待在线合成；这些优化均需要单独验证。

## 验收重点

- 口令识别后不产生 Codex 发送请求；设置和重启后的保存值一致。
- “不要换女声”“为什么取消置顶”不能当设置执行；引用、代码和混合问题保留原路由。
- “停止朗读”清除旧播放与队列；普通设置不误丢刚返回的 Codex 答案。
- 分别记录停顿、识别、意图判断、设置执行和语音确认耗时，定位真正的等待点。
- 新录音边界用安静、电脑播放、手机/电视背景声和真人同时说话分别测试；未完成的验证单独标注。
