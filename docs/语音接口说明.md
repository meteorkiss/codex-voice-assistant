# 本地语音输入接口

当前程序使用 `src/JarvisRecorder.cs` 采集麦克风音频，再由 `src/transcribe.py` 在本机识别。所有 Python 工作进程统一使用 `runtime/python/python.exe`。

## 录音

`JarvisRecorder` 提供 `Start()`、`StopToFileAsync(path)`、`Cancel()` 和 `Dispose()`。界面通过定时器读取 `IsRecording`、`IsStopping`、`Level` / `AudioLevel`、`LastVoiceUtc`、`LastFile` 和 `Error`，不通过 PowerShell 回调处理音频线程。

开始录音前必须先停止朗读。`StopToFileAsync` 不阻塞界面；录音设备释放、16kHz 单声道 PCM WAV 写完后，`IsRecording` 和 `IsStopping` 归零，`LastFile` 指向完整文件。`Cancel()` 取消录音，退出时调用 `Dispose()`。

`LastVoiceUtc` 来自音量活动阈值，供可选的停顿自动发送使用；它不是语义识别结果。无声音时保持 `DateTime.MinValue`。

## 转文字

```powershell
runtime/python/python.exe src/transcribe.py --input work/recording.wav --output work/result.json --model-dir runtime/models/sensevoice
```

模型目录包含 `model.int8.onnx`、`tokens.txt` 和 `silero_vad.onnx`。识别器不会联网下载模型或上传录音。

成功后原子写入 UTF-8 JSON，含 `ok: true`、`text`、`duration`、`elapsed` 等字段；无有效人声时 `text` 为空。失败时写入 `ok: false`、`text: ""` 和 `error`，进程以代码 1 退出。

调用方应拒绝发送空文本或错误结果。取消后的延迟结果不能发送；录音和识别临时文件在处理或取消后清理。界面与完整链路的验证方法见 [测试说明](../tests/README.md)。

## 本地任务切换口令（0.6.6）

`VoiceCommands.ps1` 解析明确的单句切换指令，保留查询原文；`LocalCommands.ps1` 分派 `switchTask`、`chooseTask`、`cancelTaskSwitch`。序号和取消仅在待选候选存在时消费。已识别切换失败不会进入 Codex 发送路径。

`TaskSwitch.ps1` 通过现有桥接进程异步发起 `{action:"find",query:"任务关键词"}`。桥接只读取已有本机候选列表，返回 `ok`、`query`、`matchType`（`unique/ambiguous/none`）、`matchMethod`（`exact/contains/phonetic/none`）、`threads`（最多五个原始候选）与 `totalMatches`。文字匹配优先于至少三个汉字的同音匹配；同音使用已有 `pypinyin`，不调用大语言模型。

查找候选不等于绑定成功。选定后沿用 `{action:"read",threadId:...}` 实时校验，只有同一请求代次、原绑定、输入状态和目标均有效才调用 `Apply-Thread` 并原子保存设置；失败恢复原绑定。查找与读取阶段分别三十秒超时，选择阶段九十秒过期。手动刷新、目录筛选、绑定、普通发送和退出清理旧选择；开始新录音使未完成的查找/读取失效，但保留候选选择阶段以便说序号。

## 本地任务创建口令（0.6.7）

`VoiceCommands.ps1` 返回 `Action=createTask`、`Value=可选标题`、`Scope=projectless/current-project`。只有明确单项口令触发；默认 `projectless`。`LocalCommands.ps1` 调用 `Begin-VoiceTaskCreate -Title -Scope`；`resumeCreatedTask` 和 `cancelCreatedTaskConnection` 分别调用恢复与放弃连接。没有待连接记录时，这两个明确口令仍在本地提示，不发往旧任务。

`src/TaskCreate.ps1` 的入口如下，业务回调仍在主线程执行：

| 接口 | 作用 |
| --- | --- |
| `Initialize-VoiceTaskCreate` | 读取已有记录；重启不重派创建、不自动绑定，可有限查询原回执 |
| `Begin-VoiceTaskCreate -Title -Scope` | 先持久化唯一请求，再启动 `voice-create` 桥接进程 |
| `Update-VoiceTaskCreate -Now` | 按状态安排只读查询或对同一真实任务编号进行有限读取 |
| `Complete-VoiceTaskCreate -Result -Context` | 接收创建／状态回执，检查请求与来源，持久化结果 |
| `Complete-VoiceCreatedTaskRead -Result -Context` | 仅在代次、来源、草稿及活动状态仍有效时保存绑定 |
| `Invalidate-VoiceTaskCreateBinding -Reason [-ReleaseSendBlock]` | 禁止旧请求自动连接；不取消已派发创建，默认继续保护后续发送 |
| `Resume-VoiceTaskCreateConnection` | 显式恢复原请求的查询或原任务编号的读取，不调用第二次创建 |
| `Cancel-VoiceTaskCreateConnection` | 放弃自动连接、解除发送保护，保留已派发请求与创建记录 |
| `Test-VoiceTaskCreatePending` / `Test-VoiceTaskCreateBlocksSend` | 分别供恢复口令和普通发送前检查使用 |

桥接创建请求为 `{action:"create",threadId:来源真实编号,requestId:唯一请求编号,scope:...,title:可选标题}`；`stateDir` 由现有桥接入口提供。默认新建独立本机任务；`current-project` 先实时读取来源目录，只接受规范路径完全一致、唯一且宿主为本机的已保存项目。Git 项目用 `worktree`，非 Git 用 `local`，不指定 `startingState`。请求不包含 `model` 或 `thinking`，新任务使用 Codex 配置的默认值，不复制来源任务的模型覆盖。

`create-status` 携带原来源编号与同一个 `requestId`，只读取创建账本；不调用创建、不连接 Codex 管道，也不负责把临时客户端编号解析为真实任务编号。回执包含 `ok`、`requestId`、`sourceThreadId`、`creationState`、`accepted`、`message`、`duplicateSuppressed`：

| `creationState` | `accepted` | 处理 |
| --- | --- | --- |
| `ready` | `true` | 必须有与来源不同的真实 `threadId` 和本机 `hostId`，再读取校验 |
| `pending` | `true` | 只有 `clientThreadId` 时不能读取或绑定；保留记录，需人工核对连接 |
| `unknown` | `null` | 可能已创建，保留请求锁，绝不重发创建 |
| `rejected` | `false` | 明确派发前拒绝；显示后端原因，不自动重试 |
| `not_found` | `false` | 账本不存在；仍在运行或无法排除已派发的进程不得因此解锁重建 |

本机状态在 `data/voice-task-create.json`，历史记录在 `data/voice-task-create-history/`，桥接账本为 `data/create-ledger.sqlite3`。派发前先写入状态，后台创建账本使用原子互斥防止同一请求重复创建；派发之后发生异常，一律按不确定处理，不把应用错误当作明确未创建。缺失或损坏的本机保护标记会保守阻止后续发送。已记录的 `ready` 与真实编号不能被迟到的缺失、错误编号或较弱回执降级。

状态查询通常间隔三秒，活跃查询最多三十秒，随后提示恢复；显式恢复只开启新一轮有限查询。创建后的本地记录尚未就绪时，最多三次读取同一编号，不再次创建。绑定或设置保存失败恢复原任务、答案、目录、读取位置和界面选择，并保留新编号供恢复；不朗读成功提示。

新录音、草稿变化、手动筛选／刷新和退出只取消自动连接资格。明确手动切换或放弃连接才解除向旧任务发送的保护；普通问题在新任务尚未连接时保留为草稿。退出清理不得终止 `voice-create` 进程；它可以继续完成回执，重启只恢复记录和只读查询。此规则不授予后台进程发送后续工作指令的权限。

验证使用实际解析、分派、主程序回调和 GUID 隔离持久化，桥接、进程和音频均为替身；未真实创建、发送或切换 Codex 任务。当前版本已加载的健康状态与隔离测试范围见 [功能记录](功能记录.md) 和 [测试说明](../tests/README.md)。
