# 声伴 0.6.18 · 免唤醒架构

更新：2026-09-21。本文是 0.6.18 的实现约束和验收依据。0.6.17 的唤醒词与短时连续接话继续保留；免唤醒默认关闭，不能用延长接话窗口、替换固定口令或“听到声音就发送”冒充。

## 本版可交付边界

本版先交付两个明确层级：

1. **仅试判**：用户显式开启后，声伴连续做本地人声分段和本地转写，显示本段被判为“上下文确认／背景或系统声／不确定”及可核验理由；绝不执行本地操作、切换任务或向 Codex 发送。
2. **实验交互**：只允许在已经存在、仍有效且绑定于当前任务的候选确认上下文中，免唤醒说“是／否／取消／编号”。确认仍走现有 `TaskSwitch` 和 `LocalCommands` 入口；普通问题、设置口令和任意指令一律只试判，不自动派发。

这不是“任意话语完全免唤醒”。当前安装只有本地 VAD、ASR 和关键词唤醒模型，没有可证明收话对象的定向语音/语义模型，也没有摄像头或经用户授权的说话人样本。手机视频、旁人和用户本人对电话说出的同一句话，在现有传感器上可能与对声伴说话不可区分。因此 0.6.18 不把词面规则称为可靠收话对象模型，也不开放普通自由话语自动发送。后续若要开放，必须先选定本地模型或经用户同意的服务、核对许可/费用/隐私、用真实反例校准，并达到另行约定的误接收门槛。

## 用户流程

- 设置页的“免唤醒实验”有三个互斥模式：`关闭`（默认）、`仅试判`、`仅上下文确认`。
- 开启前明确提示：会持续使用麦克风并在本机短时转写；不保存背景录音或历史全文。用户可随时切回关闭。
- “仅试判”时，状态区显示最近一次判定和理由，例如“试判：不确定 · 普通话语没有可靠收话对象证据”；输入框、草稿、任务和发送账本不变。
- “仅上下文确认”时，只有声伴刚刚给出单/多候选并仍处于有效确认窗口，才接受对应的肯定、否定、取消或合法编号。没有上下文、上下文过期、目标变化或编号越界时保持不执行。
- 手动录音、唤醒词、退出、关闭模式、编辑草稿、目标变化、外部程序占用麦克风、设备错误、朗读和写请求处理，都会暂停或终止本轮免唤醒采集。恢复必须重新通过安全门。

## 目录与职责

| 模块 | 单一职责 | 不负责 |
| --- | --- | --- |
| `src/NoWakeCapture.cs` | 独占一条 `EchoCapture`，保留短前滚，按人声/静音/最长时限切成有界 PCM 段；队列有上限并记录丢弃数 | 不转写、不判断收话对象、不派发 |
| `src/NoWakeDecision.ps1` | 纯逻辑地把转写、声学元数据和当前上下文变成结构化判定与理由 | 不访问麦克风、不改 UI、不直接执行命令 |
| `src/NoWakeConversation.ps1` | 管理模式、状态机、临时 WAV/ASR 工作、代次、暂停恢复和上下文确认路由 | 不创建第二条发送通道，不绕过任务模块 |
| `src/HandsFree.ps1` | 在唤醒监听与免唤醒监听之间仲裁所有权，保留 0.6.17 行为 | 不承载判定规则或免唤醒大分支 |
| `src/Assistant.ps1` | 在现有 Tick 中调用控制器、展示状态，并继续处理现有录音/ASR/发送/回答 | 不直接实现分句和判定细节 |
| `src/Settings.ps1` / `DesktopController.ps1` / XAML | 配置迁移、三态选择、明确风险提示和状态同步 | 不在创建控件或刷新时隐式开启麦克风 |

## 接口

### 采集

`NoWakeCapture.Start(captureEndpointId, renderEndpointId)` 只接受明确的输入和实际朗读输出端点；AEC 未就绪即失败，不静默退回另一只麦克风。`TryDequeueSegment()` 返回只读段对象：PCM、开始/结束时间、时长、RMS/峰值、语音帧数、静音结束原因和采集代次。`StopAndWait()` 必须确认底层 `EchoCapture` 已释放后才允许唤醒或手动录音接管。

分句只解决“哪段音频送去本地 ASR”，不能证明这句话面向声伴。前滚、起始连续人声、尾部静音和最长时限使用有界参数；达到上限的段只试判，不自动执行。待处理队列固定上限，过载时丢弃最旧未处理段并显示计数，不无限占内存。

### 判定

`Get-NoWakeDecision -Text -Evidence -Context -Mode` 返回：

```text
Disposition : accept | ignore | uncertain
Route       : none | context-confirmation
ReasonCodes : string[]
ContextId   : string
ExpiresUtc  : DateTime?
Display     : string
```

判定顺序是安全门优先：旧代次、外部采集、自身朗读、设备异常、空转写、过长段、草稿/写请求/绑定异常先 `ignore` 或 `uncertain`；只有精确、未过期的候选上下文与合法确认回复同时成立，才可 `accept/context-confirmation`。普通话语即使包含“帮我”“打开”“声伴”等词，也不能仅因此 `accept`。词面特征可以作为试判证据显示，但不是执行授权。

### 路由

`Invoke-NoWakeContextDecision` 在执行前再次核对：模式仍为实验交互、判定代次、上下文编号、来源任务、绑定代次、输入代次、过期时间、草稿为空、无未知发送、无进行中写请求。通过后停止并释放连续采集，把原转写交给已有 `Try-LocalAssistantCommand`；任务候选仍由 `TaskSwitch` 实时校验并提交。任何失败都保持原任务，不转成普通聊天、不自动重试。

## 状态机

```text
off
  └─ 用户选择模式 → starting → observing
observing
  ├─ 完整句段 → transcribing → judging → observing
  ├─ 安全门关闭 → paused → observing（重新核验后）
  ├─ 合法上下文确认 → releasing → routing → paused/observing
  └─ 用户关闭/错误/退出 → stopping → off/error
```

`transcribing` 和 `judging` 不改变输入框。每个句段携带模式代次、绑定代次和上下文快照；模式切换、目标变化、用户编辑、取消、超时或退出会递增代次，旧录音、旧 ASR 和旧判定完成后只能删除自有临时文件，不能更新状态或执行。

## 数据流与麦克风唯一所有权

```text
默认输入 + 实际朗读输出
  → EchoCapture（AEC，唯一物理采集）
  → NoWakeCapture（前滚/分句/有界队列）
  → 唯一临时 WAV
  → 现有本地 SenseVoice + Silero 检查
  → NoWakeDecision（结构化证据）
  → 仅显示，或精确上下文确认
  → 既有 LocalCommands/TaskSwitch/账本
```

`WakeListener`、`JarvisRecorder` 和 `NoWakeCapture` 互斥。切换时先请求当前所有者停止，再等待 MicGuard 扫描确认无本进程采集，最后才启动新所有者；不在两个线程之间“抢”默认设备。免唤醒使用 `EchoCapture` 的同一 AEC 路线，朗读输出端点不一致即暂停。首版朗读期间暂停试判，不把“可打断朗读”并入本次开放范围。

## 回声、旁人和手机视频

- 自身朗读：AEC 是第一层；状态机在 TTS/播放器活动时再做第二层禁止判定和路由。AEC 失效不会降级为裸录音。
- 手机视频/电视/旁人：VAD 和 ASR 仍可能得到完整文字，但普通内容只能标为“不确定”，不会派发。只有与当前候选上下文匹配的短确认可能进入实验交互；用户开启时会明确提示旁人说“是”仍可能误确认，因此窗口短、绑定精确、可随时关闭。
- 外部电脑程序使用麦克风：沿用 `MicGuard`，停止连续采集并保持 paused；不能用“没有发现进程编号”当作可继续的许可。
- 说话人/收话对象：首版没有声纹注册，也不保存用户背景样本。声纹即使加入也只能说明“谁说话”，不能单独说明“对谁说”。

## 指令、消息与上下文确认

- 普通问题：仅试判，不进入 `Send-Text`。
- 本地设置、任务创建和桌面操作：首版免唤醒不执行；仍可用现有唤醒或手动入口。
- 候选确认：只在 `TaskSwitch` 的 `choosing` 状态且上下文未过期时使用；合法回复交给现有解析器。普通“是/否/编号”在没有上下文时只是背景，不写输入框。
- 目标变化、上下文过期、候选数变化、绑定代次变化或新普通话题出现都会使确认失效，不跨任务沿用。

## 草稿、未知回执、取消与旧结果

- 输入框非空、恢复草稿存在、发送结果未知、写请求处理中或绑定不可发送时，免唤醒进入 paused；不覆盖、拼接或清空文字。
- 免唤醒不新建发送账本。未来开放普通消息也必须调用现有 `Send-Text`，继续遵守 requestId、真实目标、accepted 后清稿、unknown 不重派以及早到回答保护。
- 用户关闭模式、点取消、开始手动录音、切换目标或退出时，停止采集、撤销 ASR job、删除本轮自有 WAV/JSON，并递增代次。已经完成但代次失效的结果丢弃。
- 临时文件只位于本实例 `run-<GUID>` runtime 目录，文件名带专属 `.nowake.wav` / `.nowake.asr.json` 后缀；原子写入中间文件的 `.nowake.asr.json.tmp` 也登记为本次作业所有物。正常完成与退出精确清理这些文件。若异常退出或进程释放超时，文件可能暂时保留，下一次取得单实例锁后只清理经父目录、运行目录命名、文件名和非重解析点核验的旧免唤醒文件。不会整目录删除，因此不影响同目录内仍在等待的发送/创建/管理回执，也不碰普通 `.tmp`、个人 data 其他文件、模型或原工作树历史生成物。

## 隐私、配置和回退

- 所有分句、转写和判定均在本机；不新增上传、密钥、订阅或费用。
- 默认不保存 WAV、转写全文或误判样本。状态文件只保留模式、阶段、最近判定类别/理由码、时间、时长和丢弃计数；正常模式不写全文。
- 配置只保存 `noWakeMode=off|observe|context`，缺失、非法或旧版设置均回退 `off`。测试/预览不从个人设置自动开启。
- 关闭或故障后回到原唤醒/手动入口；不修改用户原 `handsFreeEnabled`、唤醒词、短时接话、目标、偏好和草稿。

## 测试矩阵

自动化只用合成 PCM/WAV、合成转写、设备/桥接/上下文替身，并在唯一测试目录精确自清理。

1. 分句：前滚、短噪声、安静、两句、长句上限、队列背压、停止释放、AEC 错误和端点不一致。
2. 判定：无上下文的指令/关键词/“是”均不接受；单候选是/否、多候选合法/越界编号、过期、跨任务、旧代次、自身朗读、外部采集和空 ASR。
3. 控制器：off 默认、用户切换模式、唤醒/手动/免唤醒互斥、草稿/unknown/bridge/绑定/朗读暂停、恢复、取消、关闭和旧 ASR 失效。
4. 路由：试判零副作用；实验模式只调用一次现有上下文确认入口；失败不转聊天、不清稿、不改目标、不重派。
5. 回归：0.6.17 的免手、任务切换、归档恢复、自动连接和源码依赖定向复验；不重试此前被明确拒绝的旧组合命令和 27 个历史文件清理。

## 分阶段验收

- **离线完成标准**：上述新专项通过；相关回归通过；VERSION、文档、设置迁移一致；自有生成物清理；Git 差异可复核。
- **明早真人验收（最多 5 条）**：默认关闭；开启仅试判说一句对声伴的话；播放手机视频验证不发送；制造一个候选确认并免唤醒回答；关闭后普通唤醒恢复。真人结果单列，不用离线测试替代。
- **暂不宣称**：任意自由话语自动接收、旁人/手机媒体可靠区分、朗读中免唤醒打断、长时间占用、异机安装和公开发行。缺少收话对象模型是明确产品边界，不用规则分数伪造成准确率。
