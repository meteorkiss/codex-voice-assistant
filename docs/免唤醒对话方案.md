# 免唤醒对话：可行性与实施范围

2026-09-08。用户希望不再先说“你好，声伴”，常驻监听，自行区分对助手说话、电话交流与手机外放。本文记录可实施方案；0.6.6 尚未具备此判断能力，本轮没有改变监听模式、采集样本或下载新模型。

## 能做到什么

可以新增可开关的免唤醒模式，在本机先检测人声、转写短句，再结合声音与对话上下文判断是否面向助手，判断通过后沿用原任务的发送和朗读链路。首次问题也不要求固定唤醒词。判断不明时保持安静、不自动发送，保留明确点击发送的入口。

这是概率判断，不能承诺完全区分。用户本人对电话说“帮我打开文件”，可能与面向助手的同一句话在声音和文字上相同；声纹只能提供说话人线索，不能证明收话人是谁，也不能保证排除用户本人录音的播放。

已有研究将声学特征、识别器输出和语义特征结合起来，探索取消触发短语；该研究不是可直接套用到本机中文环境的现成准确率承诺。[Apple 研究](https://machinelearning.apple.com/research/data-resource-efficient)

Amazon 在 2021 年介绍的 Conversation Mode 结合视觉与声音线索，并通过开启模式及闲置退出限定会话。它说明收话人判定需要额外上下文；本方案不默认增加摄像头。[Amazon 技术说明](https://www.amazon.science/blog/new-alexa-feature-enables-natural-multiparty-interactions)

## 现有代码可复用的部分

- 现有麦克风采集、助手播放参考与回声处理、停止播放和录音交接。
- SenseVoice 本地转写及 Silero 人声检测。当前转写为录音结束后处理；连续监听需要常驻识别工作进程、短句切分、有上限的内存缓冲与背压，不能不断启动大批转写进程。
- 当前任务绑定、过期请求代次、草稿保护、发送账本、唯一回执和完成回答朗读。
- 现有电脑上其他程序启用麦克风的检测。该信号不能证明手机是否正在通话，也不能作为所有背景声音的检测器。

## 需要补齐的部分

1. **连续人声分段。** 没有人声时维持轻量检测，有人声时切成有时限的句段；达到时限不得直接把整段背景对白自动发送。保留句首缓冲，避免开始判断时丢字。
2. **是否面向助手的判定。** 输出“可接收／忽略／不确定”及原因，结合声音、语义和当前对话状态。“你”“帮我”等词只作特征，不直接触发执行；普通聊天、引用指令和手机播放均需反例。
3. **可选说话人线索。** 可复用 sherpa-onnx 的说话人识别接口，但另需模型和用户样本，效果与体积先评估。它不能单独决定接收。[接口说明](https://k2-fsa.github.io/sherpa/onnx/speaker-identification/index.html)
4. **对话状态。** 与助手刚建立交流、刚收到助手追问时，可利用近期上下文判断后续短句；闲置后收紧判断。开始录音、结束模式、改任务、编辑草稿、外部录音及连接失效都使旧判定失效。
5. **播放中打断。** 不能因任何人声立即停读。回声处理后的句段也要通过面向助手判定，才停止旧朗读并转交问题；手机外放不属于声伴掌握的播放参考，需单独实测。

## 实施顺序

### 对话灵敏度三档

用户补充要求：设置“灵敏、普通、迟钝”三个档位，控制助手接话的积极程度。拟在界面将第三档显示为“保守（迟钝）”，普通档默认。这里调整的是“这句话在对助手说”的判定门槛，不是麦克风音量或模型回答能力。

| 档位 | 预期行为 | 取舍 |
| --- | --- | --- |
| 灵敏 | 较弱的指向线索也纳入候选，已有对话中的短句更容易接续 | 更少漏听，也更可能把聊天当成对助手说话 |
| 普通 | 在明确请求、近期上下文及声音线索之间平衡 | 默认方案，实际门槛待本机样本校准 |
| 保守（迟钝） | 需要更明确的面向助手证据才接话 | 较少误插话，但可能漏掉含糊提问 |

三档共享确定的取消、外部录音、草稿、任务变化、队列过期和发送回执保护。低置信度并不等于允许执行；试判阶段三档均不发送。不能先给任意分数设阈值再把它称为识别准确率，也不能用纯关键词规则假装已经能区分手机通话。数值门槛需依选定判定器和真实样本确定。

用户随后说“帮我新建一个任务”，又明确说明是测试并取消，该语句不作为新建任务授权或免唤醒功能上线要求。

### 从试判到自动接话

先制作本机试判模式：用户打开后，对短句只显示“认为在对声伴说／认为是背景／不确定”，不调用发送、切任务或设置执行。未发送片段在内存短时处理，不默认持久化背景音频或全文。需要保存误判样本时再单独选择。

用用户实际的直接指令、连续追问、电话对话、手机外放、电视对白、助手朗读与多人交谈验证。重点记录每小时误接收次数、漏接收、句首丢失、延迟及常驻占用，不能用文本规则单测代替真实声学验收。

根据实测选择声音分类与小型语义模型，再增加自动发送开关；模型只判定是否面向助手，保留识别原话，具体工作仍由绑定的 Codex 任务负责。模糊内容保持安静，发送仍受原来的草稿、任务代次和未知回执检查约束。

当前不承诺模型体积、响应耗时或准确率；这些需在已有机器上选定模型后测量。需要云端判断时应先说明待发送的内容和服务，现有微软朗读授权不涵盖上传日常背景对话。
