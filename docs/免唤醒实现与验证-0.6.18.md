# 声伴 0.6.18 · 免唤醒实现与验证

更新：2026-09-21。架构与安全边界见[免唤醒架构](免唤醒架构-0.6.18.md)。本版实现的是“仅试判”和“仅上下文确认”的可回退增量，不宣称已经解决任意自由话语的收话对象判断。

## 已实现

- `NoWakeCapture.cs` 使用现有 Windows AEC 路线独占采集，500 ms 前滚、连续人声起段、900 ms 静音收段、18 秒硬上限、最多 2 段待处理；过载丢弃旧段并计数，不无限积压。
- `NoWakeConversation.ps1` 负责模式和代次、唤醒/手动/免唤醒麦克风互斥、临时 WAV、本地 SenseVoice 转写、暂停恢复和自有文件清理。朗读、外部采集、草稿、未知发送、写请求、绑定异常或目标变化均暂停。
- `NoWakeDecision.ps1` 输出 `accept/ignore/uncertain`、路由和理由码。普通话语固定不产生执行路由；只有当前任务、未过期候选上下文中的合法是/否/取消/编号可进入实验确认。
- 设置页新增“关闭（默认）／仅试判·不执行／仅上下文确认·实验”。设置结构升到 8；旧设置及非法值回退关闭，测试和预览不继承连续监听。
- 状态文件只记录模式、阶段、判定类别/理由、时长和计数，不记录转写全文。临时 WAV/JSON 位于本实例 runtime，处理后精确删除。
- 确认执行仍走 `Try-LocalAssistantCommand → TaskSwitch`，不新增消息发送入口或账本；失败不转普通聊天、不重派、不清用户草稿。

## 尚未验证与明确缺口

- 没有自动开启或使用真人麦克风；未把手机视频、电视、旁人或电话对白当自动化样本。真人声学和长时间常驻仍待用户显式开启后记录。
- 当前只有本地 VAD、ASR、关键词模型，没有可验证的收话对象模型。普通自由话语因此只判“不确定”，不会自动发送。要开放任意问题需另行解决模型、许可/费用、隐私和真实反例校准。
- 首版朗读期间暂停免唤醒，不支持免唤醒打断朗读；设备切换、睡眠恢复、异机安装和发行包仍未验收。
- 上下文确认仍有不可消除的边界：候选窗口内旁人或媒体恰好说出“是/否/编号”可能误确认。窗口严格绑定当前任务和期限，但这不是声学说话对象识别。

## 2026-09-22 真人验收（最多 5 条）

1. 启动后看设置：免唤醒实验应为“关闭（默认）”，普通唤醒仍可用。
2. 选“仅试判·不执行”，面对声伴说一句普通问题；状态应显示试判“不确定”，Codex 不出现新消息，输入框不留草稿。
3. 在同一模式播放一小段手机视频；可以出现试判，但不得发送、切任务或执行设置。
4. 用普通唤醒说一个会产生任务候选的切换口令；提示候选并朗读完后，改选“仅上下文确认·实验”，直接说合法编号或“取消”，只应处理这次当前候选。
5. 选“关闭”，确认免唤醒状态结束，再喊原唤醒词；应恢复原唤醒流程。

出现误操作、持续录音无法退出、草稿被改、目标错误或普通话语被发送时立即关闭模式并记失败；不要为继续测试清空未知发送或重派消息。
