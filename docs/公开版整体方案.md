## 产品定义

一个 Windows 桌面语音入口：用户唤醒、说话，所连接的 GPT / Codex 负责回答与被授权的工作，助手显示字幕并朗读。桌面日常只显示所选的声波图形，支持环形和条形；鼠标右键声波打开菜单，也能从右下角系统托盘打开设置。声音与模型分别选择，更换声音不降低负责思考的模型。

结论：界面和多声音选择可基于现有组件实现。公开给其他人安装的主要工作是通用连接、首次配置、安装打包及兼容性验证。当前机器可用不能代替公开版验收。

## 一、桌面与托盘

| 位置 | 建议行为 |
| --- | --- |
| 桌面浮层 | 支持中间镂空的环形和横向条形声波，周围透明；默认只显示图形，不常驻底板、文字、按钮或标题栏 |
| 尺寸 | 环形约 260×260，条形使用更矮的横向容器；均可调整大小；字幕开启时显示在下方，宽约 380，具体随屏幕缩放调整 |
| 字幕 | 可选显示用户识别文字和最新答案，默认两三行；点击展开全文，长内容可滚动；保留输入纠错入口 |
| 右键菜单 | 始终置顶（带勾选）、打开设置、显示／隐藏字幕、停止朗读、隐藏悬浮声波；开始说话与暂停唤醒可从托盘或快捷键到达 |
| 拖动与键盘 | 按住声波左键拖动，普通单击不执行动作；右键打开菜单。提供键盘聚焦后打开菜单的方式；预览中可按回车，原生版同时支持菜单键／Shift+F10 |
| 置顶 | 声波右键、设置与托盘入口使用同一个开关；记住选择，不强制置顶；普通桌面操作不断读 |
| 托盘图标 | 左键打开设置，右键打开快捷菜单；Windows 可能把图标收到“显示隐藏的图标”区域，由用户控制系统显示方式 |
| 托盘菜单 | 设置、显示／隐藏浮层、置顶、暂停／恢复唤醒、停止朗读、退出 |
| 窗口关闭 | 菜单写“隐藏悬浮声波”，避免被误解为退出；只隐藏图形，后台听说按原开关继续，可从托盘恢复；关闭设置只关设置，“退出助手”才结束监听与播放 |

视觉方向：以用户给出的环形声波为参考，自行绘制可随声音变化的图形，不将素材截图直接贴到桌面。待机时圆环稳定低幅，采集时径向线条随真实音量变化，处理时使用轻微状态变化；若播放时尚未接实际音频幅度，动画只称播放指示。悬停才显示简短状态提示，字幕默认关闭。

原生版目标：环所在的一圈用于拖动与右键，镂空中心及外侧空白可点击穿透。需实测原生窗口命中、多屏缩放及细线是否方便抓取，不能仅凭视觉透明就声称已实现。实际环形频谱需要音频频段数据，现有单一音量可先驱动径向振幅；两者在实现和说明中要区分。

### 可选择的声波样式

用户新增要求：样式由使用者自己选择，形状不限圆形。第一批拟提供六种，环形保持中间镂空，条形使用适合横向显示的尺寸；所有样式保留透明周边、右键菜单与拖动：

| 样式 | 外观 |
| --- | --- |
| 彩色细线环 | 接近参考图，细密的彩色径向线条与端点，作为默认样式 |
| 柔和光环 | 连续的柔和轮廓，形变幅度较缓，中心保持透明 |
| 颗粒环 | 用疏密有变化的彩色粒子构成圆环 |
| 极简线条环 | 少量清晰线条，适合希望桌面安静简洁的使用者 |
| 彩色柱状声波 | 横向排列的彩色短柱，高度随音量／状态变化 |
| 极简横向波形 | 一条或少量横向曲线，适合较小的桌面占用 |

入口为“右键声波 → 打开设置 → 外观 → 声波样式”；选择时立即预览，保存后下次启动恢复。大小、颜色方案和动作幅度独立于样式；更换样式不重启录音、连接或朗读。

工程上统一输入音量、频段、对话状态，分别交给不同样式绘制。后续增加样式只新增绘制模块与配置，不复制整套语音助手。首次公开版先提供内置样式；以后可导入颜色、线宽和粒子密度等主题配置。

## 二、日常对话

待机 → “你好，声伴” → 回应“在” → 开始听问题 → 停顿约两秒 → 转文字 → 发到明确绑定的任务 → GPT / Codex 工作 → 显示并朗读最终回答 → 回到待机。

当前运行的 v5 是轮流听说：朗读时暂停唤醒，所以朗读期间喊唤醒词不会响应。这是当前能力缺口。按用户最新要求，**朗读中用唤醒词打断提升为第一批必须完成的语音功能**，不再只列为远期扩展；需要单独实现和验收，不能把现有版本标成已支持。

目标流程：朗读答案时持续检测用户说出的唤醒词 → 停止本次朗读并清掉未播的旧答案队列 → 回应“在” → 接住用户后续问题 → 自动发送一次 → 朗读新答案。打断朗读不会等同于取消 Codex 正在执行的任务；没有新问题时回到待机，也不自动续读刚被打断的旧答案，用户可主动重读。

唤醒后八秒没有开始说问题则返回待机；识别为空不发送。发送回执不明时提示核对，不能自动重复发送。

### 朗读中唤醒的必要设计

- 播放时只做唤醒检测，不把环境声音持续转写并发送。
- 同时取得麦克风输入和实际播放音频参考，经过回声消除，再交给本机唤醒模型。需要处理设备延迟、音量、切换扬声器和用户与播报同时说话的情况。
- 音频采集由同一个协调器管理；不能简单取消“播放时禁用麦克风”的保护，就声称实现了打断。
- 唤醒成立后立即停止当前播放器、取消待播合成结果，并让旧代次结果失效；保留屏幕上的原答案以便回看。
- 保留短暂音频缓冲，按唤醒词结束位置截取后续问题，减少用户紧接着说话时开头被吞掉。回应“在”的声音同样需要从识别输入中消除。
- 不用“答案文本含唤醒词就不监听”的过滤代替回声消除；那会使用户在同一时刻也无法打断。

验收必须包含：只有助手朗读且多次出现唤醒词时不自唤醒；用户与朗读同时说唤醒词时能停止并开始听问题；唤醒词后紧跟问题不丢开头；连续打断不重复发送；耳机、外放、不同音量分别验证。记录从唤醒词结束到停止出声的时间，再根据实测确定响应目标，不凭空承诺固定延迟。

技术验证首选 Windows 原生 AEC：通信模式的 WASAPI 采集，检查回声消除效果是否实际启用，并绑定正确的播放端点。系统支持相关接口不等于当前麦克风驱动一定提供可靠 AEC，需逐设备验证。[微软 AEC 示例](https://github.com/microsoft/Windows-classic-samples/blob/main/Samples/AcousticEchoCancellation/cpp/AECCapture.cpp)、[AEC 控制接口](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nn-audioclient-iacousticechocancellationcontrol)

若系统 AEC 不可用或实测效果不足，再接入本地 WebRTC AEC3，以麦克风与实际播放参考作为输入；这一分支需要新增原生音频组件、管理采样率和时间对齐。现有 MCI 播放器和 waveIn 单通道采集没有这些能力。[微软播放回采文档](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)、[WebRTC 音频处理接口](https://webrtc.googlesource.com/src/+/refs/heads/main/api/audio/audio_processing.h)

尚未进行设备效果测试，当前不能标注“朗读中语音打断已可用”。如果 AEC 或播放参考失效，应明确显示暂不可用并保留手动停止入口，不能悄悄用未消除回声的声音持续触发。

首次使用不同于日常使用：自动检测本机 Codex → 设置里按目录筛选、从任务下拉选择并确认绑定 → 检查麦克风与试听声音 → 明确开启唤醒。公开版不能继承本机用户已经给出的麦克风或云朗读授权。

## 三、设置窗口

| 设置页 | 第一版内容 |
| --- | --- |
| 连接与任务 | 自动检测与状态、可选目录筛选、现有任务下拉、只读校验后确认绑定、打开任务、断开／重新连接；已有任务实际工作目录只读显示；模型与思考强度显示连接实际支持的选项 |
| 声音 | 声音下拉列表、短句试听、语速、音量、自动朗读开关；显示声音来源与是否联网 |
| 唤醒与麦克风 | 唤醒开关、输入设备、输入音量检查、停顿时长；先保留已验证的默认唤醒词，自定义词需另测 |
| 外观 | 六种环形／条形声波样式、颜色方案、动作幅度、置顶、浮层大小、字幕开关、位置重置；记住选择、显示器与位置，拔掉副屏后仍可找回 |
| 常规 | 开机启动的主动选择、版本信息、打开数据目录、清理临时音频、导出不含对话和密钥的诊断信息 |

声音首批可选台湾女声、台湾男声、普通话女声／男声和英文声，按真实服务返回的可用列表筛选。微软官方目录确认有台湾女声 HsiaoChen、HsiaoYu 和男声 YunJhe。现有程序只接通两种台湾女声，不能把目录里的其他声音当成已经接通。[微软语音目录](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=tts)

当前 edge-tts 路径保留为已有适配器；公开版应同时规划可配置的官方语音服务连接。现有服务可用并不保证永久免费或持续可用。使用者自行选择声音服务、账户及额度；在线朗读明确说明答案文字会发往所选服务。

朗读速度单独设置，界面提供 0.8×、1.0×、1.2×、1.5× 等易懂选项和同一句短文本试听，并保存偏好。不同合成服务的速率参数与支持范围不同，适配器需要验证映射，不能将百分比参数直接当成精确播放倍率。方案评审阶段这些选项仅用于预览；本机 v6 已加入真实声音、语速与试听控件，由桌面控制器接入朗读设置，当前实现和验收边界见[实施框架](实施框架.md)。更改语速从下一段朗读生效，避免重播整条答案；如需立即应用，由用户明确选择重新朗读。

## 四、别人怎么连接 GPT

换电脑连接提升为公开版的核心验收项。默认主流程为：**自动检测本机 Codex → 设置里用目录筛选与任务下拉选择 → 只读校验并确认绑定 → 用户主动测试发送和回答朗读 → 保存。** 未运行或未登录时，提示用户先打开并登录自己的 Codex。目录只缩小候选列表，已有任务始终沿用自身的工作目录；未来新建任务时再单独指定创建位置。未选择或校验失败时不发送，不猜最近任务，也不静默换任务。

本机已通过“只读索引精确选中指定真实任务 → 生产 NativePipe `read_thread` 校验”片段：返回相同任务编号与本机状态，规范化目录及记录路径吻合。索引标题与实时响应有差异，绑定展示以实时响应为准。探测未发送、创建或变更任务，只保存字段摘要，见 `work/tests/bootstrap-selected-task-probe.json`。这尚不代表任务下拉、无绑定首启、新安装发送或第二台电脑已通过。详细流程和限制见[首次连接与换电脑方案](首次连接与换电脑方案.md)。

建议第一阶段优先完成 Windows 上的 Codex 伴随使用体验；同时把连接层做成可替换模块。两种连接不能混为一个“登录 GPT”按钮。

| 路径 | 使用体验 | 验证边界 |
| --- | --- | --- |
| 当前 Codex 桌面伴随连接（默认路线） | 自动检测；使用者在设置里筛选并选择现有任务，经只读校验后明确绑定；工作仍由该任务负责 | 本机索引到指定任务的只读校验已通过；管道仍是实验适配，需验证完整首启、普通安装、无 Codex 工具环境、不同版本和多个窗口 |
| 官方 Codex App Server 连接 | 由助手管理连接与任务，使用官方协议获取模型、发送问题和接收事件 | 先做独立技术验证；不能假设新服务进程可以接管桌面里正在运行的原任务 |
| 自填 OpenAI API Key | 后续可提供独立 GPT 对话模式 | 直接模型调用不会自动拥有当前 Codex 的桌面、插件和执行环境；需要另外实现工具、任务记录和授权交互 |

官方 Codex App Server 文档提供 ChatGPT 托管登录、API Key 认证、任务读写和模型能力查询，这是官方连接模块的依据；实际账号可用模型与额度仍需连接后读取。[OpenAI 官方文档](https://learn.chatgpt.com/zh-Hans/docs/app-server)

GPT‑6 保留为用户可选目标；不硬编码成所有账号都有。快速／深度是可配置的模型与思考强度组合，切换后从下一轮生效。语音新建任务、切换模式安排在基础连接可靠之后，不把讨论命令的例句直接执行。

## 五、工程框架

建议公开版使用可安装的 Windows 程序入口，保留现有本地语音工作进程。当前 PowerShell/WPF 版本用于验证；公开安装版可将桌面宿主整理为 .NET/WPF 可执行程序，减少终端和执行策略带来的安装步骤。跨平台放在后续，不能直接把 Windows 窗口与音频代码标成跨平台。

```text
桌面浮层 + 托盘 + 设置
          ↓
对话状态管理（监听、录音、发送、等待、朗读、取消）
          ├─ 音频：唤醒 / 本地转文字 / 声音服务 / 播放
          ├─ 连接：桌面 Codex / 官方 App Server / 后续 API
          ├─ 任务：绑定 / 预设 / 回执去重 / 后续语音命令
          └─ 配置：个人设置 / 系统凭据存储 / 不含敏感内容的诊断
```

模型负责思考，语音识别负责听，语音合成负责读，各自有独立接口。界面变动不改发送语义；更换声音不影响任务模型。

## 六、公开发布需要补齐

- 去掉源码中的私人任务编号、账户路径和专属互斥锁名称；无绑定时进入任务选择，不能静默投递到某个默认任务。
- 提供示例配置，首次运行生成用户自己的数据目录；不提交对话、发送记录、录音、密钥、登录资料和个人运行状态。
- 提供安装包或便携包，固定依赖版本；模型单独下载并校验，明确下载失败后的恢复入口，不能要求别人复制这台电脑的运行环境。
- 整理 README、安装和卸载说明、问题模板、版本记录；发布前确定项目许可证并保留第三方代码与模型声明。
- 完成另一台干净 Windows 的完整验证，涵盖普通账户、中文／带空格路径、蓝牙耳机、多屏缩放、无麦克风、断网与重启恢复。

目前源码还包含本机默认任务编号，所以现在的目录适合继续开发，不能直接当作完成通用化的公开安装包上传。公开仓库和对外发布属于后续步骤，本次没有执行。

连接验证仍有明确边界：无调用上下文的 `list_threads` 请求此前未成功；本机验证改由只读索引提供真实所选任务，再用生产接口读取，不能据此宣称无上下文列任务已可用。下一步要把这一段接成没有私人默认值的首启与任务下拉，并在普通安装及第二台电脑复验。本地索引和内部管道都要做版本检测，活跃 SQLite 读取须包含 WAL；索引结构未知或实时校验失败就停止绑定。目前依赖本地任务记录文件，远程／WSL 任务不在已验证范围。服务升级后缺字段的发送回执也应归为“结果未知”，不能当成明确失败后允许重复发送。

## 七、实施顺序与可行性
