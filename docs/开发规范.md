# 声伴开发规范

更新：2026-09-10。适用于后续代码整理与 GitHub 交付。已加入 .editorconfig、.gitattributes 和本地隔离回归入口；远端 CI 及新增静态检查工具仍待后续配置。

## 开发与修改

1. 功能变更先对应[功能总表](功能总表.md)中的条目，写清触发条件、结果、失败和取消行为。
2. 每次改动围绕一个可验证的问题；模块迁移与新增交互分开，避免无法判断回归来源。
3. 手动与语音入口共用业务方法。界面不发底层连接请求，适配器不改界面或全局绑定。
4. 对外输入、配置、模型输出和管道返回值均校验结构、类型和必要上下文；外部文本不作为 shell 代码。
5. 长时工作不阻塞界面线程；音频回调不等待网络、磁盘整理或界面锁。
6. 取消先使上下文失效再清资源；未知写操作保留记录，禁止当作肯定未执行而自动重试。

## 语言与编码

| 范围 | 约定 |
| --- | --- |
| PowerShell | 保持 Windows PowerShell 5.1 兼容；中文脚本使用 UTF-8 BOM；函数采用 Verb-Noun；避免新增无边界的 script 全局状态 |
| Python | 公共接口添加类型标注；分层异常；统一格式与静态检查配置；依赖固定版本 |
| C# | 类型与公共成员 PascalCase，局部变量 camelCase；资源明确 Dispose；严格核验线程和音频锁的边界 |
| XAML | 绑定展示状态，交互调用统一入口；界面文本集中管理，保持中文反馈一致 |
| 文档与配置 | UTF-8；实际换行；配置示例使用虚构数据；JSON 对外协议增加版本并支持旧格式迁移 |

`.editorconfig` 与 `.gitattributes` 已建立，各语言检查配置随后补充。先选择与当前运行版本兼容的工具版本，再加入开发依赖；不因格式整理升级整个运行栈。

## 错误、状态与日志

- 错误区分参数问题、无能力、连接失败、设备失败、拒绝、超时和结果未知。
- 提示说明当前结果和可行下一步，不将合成失败误报成任务失败。
- 诊断只记录必要状态、耗时、错误码及关联编号；不默认记录聊天全文、背景转写、密钥或音频。
- 本机业务账本所需的真实任务编号等保存在私有数据区；导出诊断时脱敏。
- 所有文件操作核验所属目录。清理不能扩大到用户工作目录、历史模型或其它进程文件。

## 测试与验收

| 层级 | 验证内容 | 运行条件 |
| --- | --- | --- |
| 单元 | 解析、类型、匹配、状态转移、文本过滤 | 虚构数据，不依赖账号和设备 |
| 集成 | 实际业务函数及异步接线，桥接和音频使用替身 | 独立临时目录，不读取日常助手的测试状态 |
| 组件与接口 | 实际编译、模型加载、连接能力、回执与操作核对 | 明确区分只读和真实写操作，记录测试对象并清理自建资源 |
| 设备与真人 | 播放中唤醒、句首保留、背景声、续播、插拔、睡眠和长期运行 | 记录硬件、模式、样本条件及未通过项 |
| 安装与升级 | 干净电脑、用户自己的账号、配置迁移、重启、更新和回退 | 不借用开发者账号、任务编号或模型缓存 |

故障测试重点覆盖：迟到回调、读写失败、回执丢失、重复请求、资源未释放、任务变化、新草稿、退出和重启。测试断言针对外部行为，不仅复述实现。纯文案与可逆低影响修改不添加机械测试。

每个测试脚本明确输入、输出目录、是否联网、是否打开设备和是否修改真实任务。需要单独 TestMode 进程的脚本必须验证进程与运行标识，拒绝读取历史状态冒充当前测试。一次性录音、截图、回执、源码副本和测试数据必须在结束后清理；保留有维护价值的测试源码和简短结论，失败也不默认永久保留整个目录。

## 版本与依赖

根目录 `VERSION` 是程序与启动器的版本来源。修改版本后同步 README 当前版本和 CHANGELOG 首条说明，构建会核对两者；程序集版本在构建时生成，不另行手填。修复与小功能记录在更新日志；破坏配置或接口兼容的改动提供迁移说明。开发、预发布和正式发行状态明确区分，不仅靠版本数字暗示验收完成。

Python 包、音频组件和模型各有清单，包含版本、来源、校验值和适用环境。开发工具与运行依赖分开；模型按需准备，不能靠复制整台开发机环境完成构建。

## GitHub 仓库与发行

目标仓库：`https://github.com/meteorkiss/codex-voice-assistant.git`。

源码仓库应包含源码、脱敏测试样本、构建脚本、依赖清单和使用文档。发布准备补齐许可证、第三方声明、贡献说明、问题反馈与安全问题报告渠道、PR 模板和自动检查。许可证的具体选择和第三方模型分发条件需在公开发行前明确。

个人 `data`、聊天、录音、账本、缓存、开发实验与环境包排除在源码提交之外。`.gitignore` 之外，打包采用明确文件清单，并检查实际暂存文件。实验音频和模型不因可下载或已有样音就默认具备再分发条件。

可执行文件与必要依赖通过单独发行流程生成；当前根目录 exe 不直接视为源码。发布流程检查来源清单、版本、依赖、安装验证、校验值和回退说明。创建一个空远端仓库不等于源码已经上传或发行包已准备好。

自动检查先覆盖无账号、无音频设备的测试；真实设备和个人账号操作不放入普通 CI。提交说明围绕具体问题，PR 写清行为变化、验证结果和实际限制，不贴私人日志。

参考：[GitHub 项目 README](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)、[GitHub 大文件与发行说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)。
