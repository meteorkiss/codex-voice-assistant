## 当前交付

0.6.16 已完成本批稳定性修复与模块整理，相关回归和依赖核对见[晨间验收](晨间验收.md)。2026-09-12 用户明确要求本轮上传现有 GitHub 仓库源码，并转入后续功能。既有文档中的“未上传”保留原记录日期的含义，实际上传结果以 Git 远端为准。

当前收口包括：绑定与草稿保护、常用设置共用保存回退、音频输出所有权与取消清理、版本与构建检查、依赖快照、16 组离线回归。不得将这些再次作为未开发功能。

仍缺少的真人、设备、异机安装、发行许可和远端检查分项记录，不因开发任务归档就标为通过。旧纯 Git 导出回归命令曾被自动审批阻止，不能重试或绕过；普通 CI 或源码布局检查的结果如实单列。

## 下一版：0.6.17 短时连续接话

范围对应功能总表 N02，并只纳入必需的 N05 录音边界保护：用户主动启用后，在明确唤醒交流、回答播放结束后，开放有时限的下一句接话窗口，减少每次重复唤醒。闲置、取消、草稿编辑、目标切换、连接异常或外部麦克风占用结束该窗口。窗口内保留句首、限制录音时长，模糊结果不自动派发。

保持默认关闭；窗口期间给出清楚的可见状态与结束入口。不要把它描述成已能识别电话、电视或所有背景对白的完全免唤醒。声音采集、回声处理、转写、发送账本与既有生命周期优先复用。

先根据当前源码细化一个小范围实现，再做设置持久化、窗口超时与取消、旧回调、草稿保护、目标变化、播放结束交接等相关回归。真人体验只验新接话窗口与受影响路径；未发生变化的基础功能不重新安排整套验收。

## 后续选题与收口

0.6.17 完成后，从功能总表中尚未实现且前置条件具备的需求选下一项，推荐先处理明确设备设置、模型预设或指定项目新建；完全免唤醒及三档灵敏度要先具备可校准的判定器，不能用简单关键词冒充。仅支持已记录范围，微信保持暂不开发。

每版交接写清：实际提交与版本、本版变化、已通过的相关检查、临时产物清理、尚未验证事项、下一版范围和是否需要真人参与。Git 同步和新任务接手确认后再归档前一任务；失败时保留能继续处理的任务并说明实际阻碍。
