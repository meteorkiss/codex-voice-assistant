更新于 2026-09-09。以 **0.6.9 为当前基线**。声伴负责桌面语音入口和明确的本地操作，任务中的思考与工作交给 Codex 所选模型。先把听说和任务连接做可靠，再整理可交付的小版本，之后增加新能力。

## P1 已有什么证据，还缺什么

- 默认语音新建独立聊天；明确说“在当前项目新建”才按当前任务目录精确匹配已保存本地项目。Git 项目使用 worktree，非 Git 使用 local。无匹配、多匹配或项目元数据不完整时停止，不猜选。
- 创建先持久保存请求；进入创建调用后，任何异常都保留为结果未知。重启和查询只核对原请求，不重复创建。已知真实任务编号不会被较弱的迟到回执覆盖。
- 2026-09-09 的重点隔离检查：TaskCreate 12 个场景、115 个检查通过；TaskSwitch 12 个场景、206 个检查通过。使用真实生产函数与隔离状态文件，桥接／音频等外部动作使用替身，未在检查中创建或发送真实任务。
- 用户已实际创建的一个新任务，其真实编号经过一次生产桥接只读校验：返回编号一致、主机为本地、本地记录存在。只保存字段摘要，未保存聊天内容；没有改变声伴绑定。这证明真实新任务可读，**不能单凭这一项宣称语音新建与下一轮提问的完整链路已验收**。
- 项目创建若只返回临时 `clientThreadId`，当前没有已验证的公开映射接口，保留待核对状态。不能用临时编号读取真实任务，也不能按最近时间或相似标题猜测。Git worktree 的真实创建与准备过程仍待实测。
- 手动连接要补的保护：已有草稿不应被直接清除；读取目标期间的新录音、新文字、取消或当前任务变化，必须使迟到绑定失效。与语音入口保持一致后再验收。

本轮摘要在 `work/tests/task-priority-review-20260909/`；真实聊天内容不纳入调试报告。

## 稳定小版本之后再做

以下按顺序推进；均为后续计划，不能作为当前已完成能力介绍。

| 顺序 | 功能 | 实现边界 |
| --- | --- | --- |
| 1 | 模型与语音预设 | 设置里配置“快速”“深度”等标签，语音切换可用模式；沿用 Codex 提供的模型和推理强度，不强制新增 API Key。切换只影响后续请求，不重跑进行中的回答。 |
| 2 | 在任选项目新建任务 | 从真实项目列表明确选择，处理重名和歧义；目前只支持独立任务或精确匹配当前项目。 |
| 3 | 复合语音命令 | 例如“新建任务，然后帮我整理这个问题”。需要分步状态、明确目标和失败保护；目前不能把多步口述随意拆成会执行的操作。 |
| 4 | 更轻、更自然的台湾女声 | 保留现有可用声音，优先合适的现成方案；先试听、核对体积和接入条件，再决定采用，不默认打包大体积本地模型。 |
| 5 | 麦克风与播放设备设置 | 显示并明确选择输入／输出设备，处理设备断开、默认设备变化和回声消除的播放端点一致性。 |

## 交付与验收原则

先完成范围明确的小版本，记录“已实现、隔离测试通过、真实链路通过、另一台电脑通过”四种不同状态。发布前覆盖账号与任务选择、语音收发、异常恢复、退出和更新；需要新增外部服务时先明确接入和授权条件。

整理目录不会自动删除历史实验、模型或个人数据。公开交付清单与本机使用目录分开管理，未完成的免唤醒、微信或任务归属移动不写成已上线功能。
