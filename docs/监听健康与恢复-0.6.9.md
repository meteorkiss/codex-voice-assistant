# 0.6.9 监听健康与恢复

本次优先处理“声波有变化，却无法知道唤醒识别是否仍在工作”的诊断和恢复缺口。保留现有唤醒词、0.35 门槛、台湾女声、任务绑定及其他偏好。

## 实现范围

- 唤醒程序每实际处理约半秒音频，回报累计处理量；没有收到音频时不产生虚假的定时心跳。静音也有连续的音频数据，因此不会因为房间安静而反复重启。
- 同时检查采集新鲜度、模型处理新鲜度，以及采集到处理的总积压。开始监听允许十秒准备时间；已开始后的三秒停滞或积压超过三秒会撤销“就绪”。计时使用单调时钟。
- 已识别唤醒词后，关键词程序正常完成，不再要求它继续回报；问句交接仍检查同一条回声处理采集链路。
- 故障时停止旧音频并作废未完成录音的自动发送。正在进行的 Codex 请求不取消，已有文字草稿保留；恢复期间新到的回答在队列中等待。
- 等原采集确实释放、麦克风会话有新扫描且没有占用后，按三、六、十二秒间隔尝试恢复，五分钟内最多三次。驱动八秒内仍未释放时停止自动尝试，提示重新打开声伴，不另开第二条输入。
- 系统默认音频设备变化或界面计时出现长间隔时，等当前听说结束再重建。刚检测到的唤醒不会被这一步吞掉。设备选择界面尚未增加。
- 状态文件新增真实采集量、处理量、新鲜度、健康原因和恢复阶段，不包含音频内容。
