# 声伴：首次连接 Codex 与换电脑方案

2026-09-08 · 设计与验证状态。本页描述要实现的流程，不是当前 v5 已提供的安装说明。

## 用户应该怎么操作

主流程是：**自动检测本机 Codex → 设置里按目录筛选、从任务下拉选择 → 只读校验并确认绑定。** 每台电脑上的声伴先连接同一台电脑上的 Codex，以后打开助手重新校验并恢复有效绑定。

1. **安装并打开声伴。** 首次显示“连接 Codex”，检查本机环境。需要的组件由安装流程解释并提供安装入口，不让普通用户修改源码。
2. **自动检测本机 Codex。** 默认连接桌面已有任务；未运行时提示打开，未登录时由使用者在 Codex 完成登录。检测进程、发现连接和成功读取任务分别显示，不靠检测到进程就显示“连接成功”。
3. **在设置中选任务。** 只读读取本机任务索引，展示任务下拉；可用工作目录缩小列表，未指定筛选时展示符合条件的本机候选。由用户明确选择，不能猜最近任务。没有候选时显示原因与重新检测入口，不伪造任务编号。
4. **校验并确认绑定。** 用所选真实任务编号调用桌面只读接口，再展示实时任务名称与工作目录供确认。索引只提供候选，实时响应决定最终绑定信息。已有任务沿用它本身的工作目录，目录筛选不会改变它；新任务的创建位置属于另一个需要用户明确触发的功能。未选或校验失败时保持“尚未绑定”，不能自动换任务。
5. **选择模型与声音。** 模型以当前账号实际可用列表为准；保持用户选择的模型与思考强度。声音可试听，语速可调整。
6. **测试连接。** 页面展示一句固定测试话，例如“只回复：连接成功”。用户点“发送测试”后只发一次，收到目标任务的完成答案并成功朗读后，分项标记通过。
7. **保存并进入桌面浮层。** 保存非敏感的目标任务编号、目录筛选和声音偏好；任务实际工作目录作为读取的信息显示。下次启动重新检测并恢复有效绑定；连接或任务失效时打开修复入口，不自行换任务。官方后端可作为单独的后续连接选项，能力边界见下文。

测试步骤会在所选任务里产生一条真实消息，因此按钮必须展示发送内容和目标。仅检测状态不会向任务发送消息。

## 设置页要展示什么

建议“设置 → 连接与任务”包含以下状态和入口：

| 项目 | 界面含义 |
| --- | --- |
| Codex 组件 | 已找到、未安装、版本不兼容 |
| 账号 | 已连接、需要登录、账号当前不可用；具体状态须由连接接口返回 |
| 目录筛选 | 可选，用来缩小任务列表；不修改已有任务的工作目录 |
| 目标任务 | 任务下拉、明确选择与确认绑定；任务名称及实际工作目录在只读校验后更新 |
| 连接状态 | 未连接、正在连接、可读取、可发送、需要核对 |
| 完整测试 | 读取任务 → 一次发送 → 收到完成答案 → 成功朗读，分别报告结果 |
| 操作 | 重新检测、登录／重新连接、选择任务、发送测试、打开任务、断开 |

GPT 能回复而声音服务失败时，保留答案并说明朗读失败，不把它误报为 Codex 断开。发送后回执未知时保留请求记录，不能自动再发。

## 两条连接路线的差别

### A. 桌面已有任务伴随模式

这是用户当前的主要需求：继续使用 Codex 图形界面里选定的任务，语音助手给它送入文字，再读出完成答案。Codex 界面、已有任务及操作权限仍有各自的作用，助手明确绑定一个任务。

本机 v5 已通过内部管道做到该流程，但它是实验适配，尚不能作为“任意电脑安装即用”的公共保证。候选发现可先读取本地索引，再让用户选择真实任务，由桌面接口校验。当前需要解决：

- 原来的默认任务编号写在源码里，必须去掉，改为使用者自己的明确选择。
- 将“只读索引候选 → 用户选中真实任务 → 桌面只读校验”接入无绑定首启与设置下拉；本机这一段已通过下述最小验证，完整向导尚未实现。
- 普通用户安装 Codex、尚未运行任何带工具的任务时，所需连接是否存在，尚未验证。
- 多个实例、版本升级、任务记录格式变化和非本机任务，可能使现有发现或读取方法失效。

#### 本机已经验证的连接片段

2026-09-08 的最小只读验证通过：从当前本机 `state_5.sqlite` 精确查到已明确指定的现有任务，再使用生产 bridge 的连接发现及 `read_thread` 方法，返回了同一任务编号、本机宿主和活动状态。规范化后的工作目录与记录路径一致，记录文件存在。结果保存在 `work/tests/bootstrap-selected-task-probe.json`；未保存聊天内容，未发送消息、创建任务或改变任务。

| 检查 | 结果与含义 |
| --- | --- |
| 本地索引 → 明确选中真实任务 | 通过；只查授权的指定编号，没有猜最近任务或读取其他候选内容 |
| 发现连接 → 生产桌面只读接口校验 | 通过；使用生产调用包装及真实来源任务编号，未临时编造来源任务 |
| 索引与实时元数据 | 标题有差异，目录和记录路径规范化后相符；以实时返回的名称、目录为准 |
| 无绑定首启、任务下拉、确认保存 | 尚未接成完整用户流程 |
| 新安装发送与朗读、第二台电脑 | 本次未验证；已有 v5 的链路结果不代替新安装验收 |

活跃索引以只读连接打开并包含当前 WAL 数据；本次使用 `mode=ro` 与 `query_only`，未使用会忽略 WAL 更新的 `immutable=1`。公共适配器要检测实际索引版本与字段，不能假定各版本永远叫 `state_5.sqlite`。排除归档与子任务候选，所选任务还须经实时接口确认是本机 Codex 任务；索引结构未知或校验不符时停止绑定。

此前省略任务／轮次／调用上下文的 `list_threads` 请求返回过 `Invalid app tool request`。这一请求形式仍未打通，也不能据此推断究竟哪个字段必需。新验证走的是“索引提供真实所选任务 → 只读校验”，并没有证明无上下文 `list_threads` 已可用。读取成功只说明这一段可读取，不能直接显示发送及完整首启均已通过。

首选流程不要求用户手填任务编号或先运行配对命令。若以后需要增加配对备用路径，必须先把正式插件／工具协议与本机配对实现出来，并验证它能提供所需上下文。当前没有这样的现成配对命令，不能让用户执行虚构命令、随便填任务编号或复制另一台电脑的登录资料。

一个待验证候选是：助手生成一次性配对码，用户在目标任务中触发配对，由安装好的本机 helper 接收 hook 的来源信息，再在助手中核对任务名称。官方 hooks 文档确实提供会话、工作目录和部分轮次上下文字段；但会话编号与准确任务编号的映射、桌面版本支持、管道持续收发都要继续验证。hook 只帮助识别来源，不会自动授予内部管道发送权限。[OpenAI hooks 文档](https://learn.chatgpt.com/zh-Hans/docs/hooks)

### B. 官方 Codex 后端模式

公开版的长期连接模块可基于官方 App Server。助手在本机通过标准输入输出管理该服务，用官方认证和任务协议工作。官方文档提供认证状态、ChatGPT 登录、API Key 方式，以及任务列表、新建与恢复接口。[OpenAI App Server 文档](https://learn.chatgpt.com/zh-Hans/docs/app-server)

可设计为“检测组件 → 官方登录 → 选择项目 → 新建或恢复该连接可管理的任务 → 接收结果”。使用者不必为了该模式一律自填 API Key，账号权益与可用能力仍以实际认证结果为准。[OpenAI 身份验证文档](https://learn.chatgpt.com/zh-Hans/docs/auth)

这里的“恢复任务”不能自动解释为接管另一个桌面进程正在执行的任务。进行中的轮次、工具上下文、权限确认和版本支持必须由同一连接正确管理。若两种模式能力不同，界面应明确标识，不能连接失败后无提示换到另一个任务。

### 路线建议

优先实现 A 模式的自动检测、设置内目录筛选／任务下拉与确认绑定，承接已经通过的本机只读片段，再验收无绑定首启和第二台电脑。连接层保留 B 模式的独立适配位置；如果 A 在其他安装或版本上不能稳定工作，应明确说明兼容范围，不能无提示地另开后端代替原桌面任务。

实现顺序提前为：**连接验证 → 完整语音往返 → 安装到第二台干净电脑复验 → 再完成公开安装包。** 声波皮肤与设置可以并行开发，不能替代连接验收。

## 换电脑时迁移哪些内容

- 可迁移偏好：皮肤、颜色、字号、语速、声音名称；新机器不支持的声音要重新选择。
- 需重新确认：本机工作目录、麦克风、扬声器、Codex 连接和目标任务。
- 账号通过官方流程登录。源电脑的任务、正在执行的工作和本地文件，不因复制助手目录就自动迁移。
- 跨电脑远程控制、任务历史迁移是另一项功能；本页首版范围是每台电脑独立连接本机 Codex。

## 发布前的通过标准

在不带开发者私人配置的第二台 Windows 上，从安装开始，用使用者自己的账号完成连接、明确绑定、发送一条问题、读取同一任务的答案并朗读；关闭重开后仍指向同一个有效任务。全过程不修改源码、不填写私人任务编号、不借用开发者的运行记录。

同时验证 Codex 未运行、未登录、版本不兼容、任务被删除、输出设备切换、发送超时、语音服务失效与重启。公开版应显示可执行的修复入口，未知回执不重发，失效任务不自动替换。
